# Mission Book — 数据落地与平台

> 本文档回答三件事：
>
> 1. [数据模型](数据模型.md) 里的对象如何落到本地数据库
> 2. 外部 AI 生成的 Goal 大纲如何安全导入
> 3. Windows 与 Android 上已经确认的平台约束
>
> 技术选型：Drift + SQLite。这一版从**空数据库**开始，不继承任何历史 Schema。

---

# 第一部分 — 存储

# 1. 表

```text
goals
goal_nodes
missions
mission_schedule_revisions
execution_plans
execution_events
evidence
failure_records
```

只建这八张表——它们与 [数据模型](数据模型.md) 的对象一一对应。

**不建的表**：

```text
plans / plan_revisions   没有创建入口（Plan 编辑器不在这一版）
evaluations             没有 AI，产生不了记录
context_states          这一版不实现
progress_states         这一版不实现
```

不提前建空表，也不写"以后会用"的字段。见 [数据模型 §1.6](数据模型.md)。

可选：如果希望追溯"这份大纲是从哪个 JSON 导进来的"，增加 `goal_outline_imports`（保存原始 JSON 与导入时间）。它是审计数据，**不参与业务查询**。不加也不影响任何功能。

---

# 2. 关系

```text
Goal 1 ──── * GoalNode
  │              │
  └──────┬───────┘
         ↓
      Mission 1 ──── 1 ExecutionPlan
         │
         ├── * MissionScheduleRevision
         ├── * ExecutionEvent
         ├── * Evidence
         └── * FailureRecord
```

所有外键在 SQLite 中启用并接受自动化验证。

---

# 3. 存储规则

```text
ID            使用 Text，值为客户端生成的全局唯一 ID
Enum          使用稳定字符串名称，不使用 ordinal
DateTime      以 UTC 保存
Duration      使用整数毫秒
GoalNode      使用 parent_node_id + order_index 保存 Tree
```

- Aggregate 内部的不可变有序列表可以编码为 JSON Text，例如 ExecutionPlan 的 steps。这类字段只整体读写，不参与 SQL 查询条件。
- 用户确认过的导入原始 JSON 只保存在 `goal_outline_imports`（如启用），**不是业务查询来源**。

## 为什么 ID 用客户端生成的全局唯一 String

这一版不做同步，但未来如果要加服务器，本地 ID 不需要重写。因此：

- 使用客户端生成的全局唯一 ID
- 时间统一 UTC 持久化，展示时转本地
- 历史对象追加式：不覆盖 ExecutionEvent、Formal Evidence

**但不要为此增加** `userId`、`syncState`、`serverVersion`、`tombstone` 或冲突合并逻辑——那是在为不存在的服务器写代码。

---

# 4. Evidence 附件

`evidence` 表保存三个 nullable 附件字段：

```text
attachment_storage_key   TEXT NULL
attachment_file_name     TEXT NULL
attachment_mime_type     TEXT NULL
```

- `attachment_storage_key` 是应用私有目录下的**相对键**，例如 `evidence/<missionId>/<attachmentId>.png`。
- 数据库**不得保存** Windows 盘符、Android content URI 或来源文件的绝对路径。
- `content` 保存文字内容或附件的可读名称。
- Data 层负责把相对键解析为当前设备上的应用私有绝对路径。
- Finalize 只把 Draft 中已保存的相对键写入 Formal Evidence，**不复制第二份文件**。
- 无附件的 Formal Evidence，三个字段全部为 null。

---

# 5. 事务边界

以下操作必须各自在一个 Transaction 中：

```text
ImportGoalOutline
CreateMission
StartMission
PauseMission
ResumeMission
ExtendMission
EndMission
FinalizeEvidenceSubmission
ApplyEvidenceDeadline
```

业务状态校验发生在 Application Workflow，Data 层只保证事务与约束。

AI 调用（未来）不属于事务的一部分：用户提交的 Evidence 保存成功即可，不能因为 AI 请求失败而回滚。

---

# 6. Schema 与 Migration

- **本版从一个全新的 schema 开始，schemaVersion = 1。** 不继承任何历史版本或迁移记录。
- 每次修改 Schema 必须递增版本，并写对应的 `onUpgrade`。
- **禁止在正式启动时删除数据库重建。**
- Migration 必须有升级测试和数据保留断言。
- 开发环境清空数据只能通过显式开发操作，不能成为正常启动逻辑。

需要自动化验证：

```text
1. 冻结的当前 Schema 与 AppDatabase 一致
2. 冻结的历史 Schema 可以执行正式 onUpgrade 并迁移到当前版本
3. Formal Evidence 的附件元数据在数据库关闭并重开后保持
```

# 第二部分 — Goal Outline 导入

# 7. 协议定位

```text
JSON = 版本化的输入协议 ≠ GoalNode 的运行时存储格式
```

它的用途：让用户把**外部 AI 生成的大纲**安全地导入 Mission Book——这是没有内置 AI 时，唯一能拿到"AI 规划的结构"的入口。

导入是**一次性创建**：创建一个新 Goal 和它的大纲。

---

# 8. 标准结构

```json
{
  "schema": "mission-book.goal-outline",
  "version": 1,
  "goal": {
    "title": "掌握 Flutter 应用开发",
    "description": "能够独立开发和维护跨平台 Flutter 应用",
    "why": "用于完成 Mission Book 并形成可展示的项目能力"
  },
  "nodes": [
    {
      "key": "navigation",
      "title": "Navigation",
      "description": "页面导航与 Route Stack",
      "children": [
        { "key": "route-stack", "title": "Route Stack" }
      ]
    }
  ]
}
```

# 9. 字段

## Root

| 字段 | 类型 | 必须 | 规则 |
| --- | --- | --- | --- |
| schema | String | 是 | 固定为 `mission-book.goal-outline` |
| version | Integer | 是 | 当前只接受 `1` |
| goal | Object | 是 | 新 Goal 内容 |
| nodes | Array | 是 | 可为空 |

## Goal

| 字段 | 类型 | 必须 | 规则 |
| --- | --- | --- | --- |
| title | String | 是 | Trim 后非空 |
| description | String | 否 | |
| why | String | 否 | |

## Node

| 字段 | 类型 | 必须 | 规则 |
| --- | --- | --- | --- |
| key | String | 是 | 单次导入内唯一 |
| title | String | 是 | Trim 后非空 |
| description | String | 否 | |
| children | Array | 否 | Node[] |

**防护上限**（防止异常输入拖垮应用，不是产品规则）：

```text
单个文件不超过 2 MB
嵌套深度不超过 12 层
节点总数不超过 500 个
```

超出时给出明确错误，说明是哪个限制被触发。

## 不允许外部输入的字段

```text
id / goalId / parentNodeId / orderIndex / status / createdAt / updatedAt
```

这些由应用在用户确认导入时生成：数组位置生成同级 `orderIndex`，嵌套结构生成 `parentNodeId`。

---

# 10. 导入流程

```text
选择 .json 文件 / 粘贴文本
   ↓
解码
   ↓
校验
   ↓
Tree Preview + 错误 / 警告
   ↓
用户确认
   ↓
一个事务写入
   ↓
Goal + GoalNode[]
```

- 文件读取后立即进入校验与预览；**用户确认前不写入任何业务数据**。
- 解析或任意写入失败时，不得留下部分 GoalNode。
- 文件只是输入载体，不成为新的领域对象。
- Android 复用系统 `ACTION_OPEN_DOCUMENT`，不申请外部存储权限；Windows 使用系统文件选择。

## v1 的边界

v1 只支持"创建一个新的 Goal 和大纲"，**不支持**：

```text
把 JSON 自动合并进已有 Goal
用 JSON 覆盖已有 Tree
根据标题猜测相同节点
自动删除旧节点
```

已有 GoalNode 通过应用内的编辑能力维护。未来如果要做 Merge，必须先提供 Diff Preview 和冲突规则，再升级协议版本。

## Provenance（可选）

如果保存导入记录：

- Raw JSON 不参与页面业务查询
- Raw JSON 不覆盖已规范化的数据
- 记录导入来源（如 `EXTERNAL_AI_JSON`）与确认时间

# 第三部分 — 平台约束

> 这些是在真实设备上确认过的边界，不是设计偏好。实现时必须按这里处理。

# 11. 计时与进程

- 计时**不依赖常驻定时器或前台服务**。Mission 的真实时间始终由 ExecutionEvent 的 `occurredAt` 计算，页面上的计时器只刷新显示。
- 普通关闭、系统回收、从最近任务划掉应用：数据库里的 Running / Paused 与事件时间线仍在，重新打开后按真实事件时间继续计算。
- Android「强行停止」是系统级封锁：系统会移除通知并阻止闹钟与 Receiver，直到用户再次手动打开应用。**Mission 数据不会丢失**，启动后恢复状态与通知。

# 12. 通知

- Android 13+ 在用户第一次使用提醒或开始任务时请求通知权限。
- Fixed Mission 优先请求精确闹钟权限；未授权时任务仍然保存，退回非精确调度，并明确提示可能延迟。
- Android 重启后由系统 Receiver 恢复已安排的提醒。
- Windows 使用本地 Toast。未打包应用受 Windows package identity 限制——**这一条必须在 Windows 上人工确认当前分发形态**，不要假设未打包应用一定能弹出 Toast。
- 通知是数据库事实的系统级投影，不是第二套状态：
  - Running 显示任务标题、当前 Focus 摘要与"停止"
  - Paused 显示任务标题、Focus 摘要与"继续"
  - 点击通知主体进入当前任务
  - START / PAUSE / RESUME / END 后立即更新或清理通知
  - **应用启动时从 Mission + ExecutionEvent 重新对账通知**
- "停止"不能静默写 END——END 还需要 COMPLETED / NOT_COMPLETED 以及对应凭证或失败原因。点击"停止"后先写 PAUSE，再打开结束确认。
- 「延后 15 分钟」属于通知投影：不修改原 `fixedStartAt`，不创建新的 ScheduleRevision，也不写 ExecutionEvent。启动对账时如果系统里还有待投递的延后提醒，必须保留它。

# 13. 文件与权限

- 选择文件统一走系统选择器：Windows 用系统文件对话框，Android 用 `ACTION_OPEN_DOCUMENT`。
- **不申请外部存储权限。**
- 临时选择缓存应在下次启动或下次选择前清理。
- 附件复制进应用私有目录后，不再依赖来源文件的存在。

# 14. 图标与品牌资产

需要交付：

```text
1024 px 品牌母版
Android legacy launcher icon（mdpi–xxxhdpi）
Android adaptive icon foreground / background
Android 13 themed monochrome icon
Android 白色透明通知小图标
Windows 多尺寸 ICO
```

- Android 自适应图标在圆形 / 方形裁切下都不被切掉关键图形；通知栏小图标必须是单色可辨识图形。
- 仓库保留可重复生成的脚本，避免各平台图标日后漂移。
- 品牌资产以 `ui设计手册/封面.png` 为准。
