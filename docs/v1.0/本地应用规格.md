# Mission Book — 本地应用规格

> 这一版要做出什么：在没有内置 AI、没有服务器的前提下，一个可以真实、连续使用的本地应用。
>
> 平台：Windows + Android。两端都是一等支持平台，但 SQLite 数据彼此独立，**不提供跨设备接力**。
>
> 本文档只写产品边界与验收口径，不写技术选型、不写目录结构、不写界面细节。

---

# 1. 这一版的定位

Local First。先把"一个人真的能连续用下去"这件事做出来：

```text
创建 Goal / 导入 GoalNode 大纲
   ↓
手动创建 Mission
   ↓
Today
   ↓
Start / Pause / Resume / Extend / End
   ↓
Evidence / Self Report
   ↓
Result（智能评价明确显示暂未接入，不生成模拟结果）
   ↓
关闭 App、重新打开后继续使用
```

这一版最重要的不是功能多，而是**状态真实**：

- 执行时间来自真实事件，不是估算
- 完成情况来自用户报告与证据，不是推断
- 关掉应用再打开，一切都在

---

# 2. 必须包含

- 本地持久化，应用重启后数据完整
- Goal 手动创建、编辑
- Goal Outline JSON 导入（文件选择或粘贴 → 校验 → 预览 → 确认）
- GoalNode Tree 展示与最小编辑能力（新增、改名、删除、调整顺序）
- Mission 手动创建；从 GoalNode 进入时预填节点标题、说明与 Goal 的 Why
- Mission、ExecutionPlan、ScheduleRevision 原子保存
- 完整 Lifecycle 写入的事务保证
- 启动加载、失败提示与重试
- Running / Paused / Evidence Pending / Evaluation Pending 的重启恢复
- Windows 与 Android 两端可构建、可实际使用
- 首页展示最近 7 天与近 30 天的执行情况
- Goal / GoalNode 展示关联 Mission 的完成情况
- Evidence 支持文字、代码、图片、文件、手动记录
- 通知：Fixed Mission 到点提醒；Running / Paused 期间的执行通知

---

# 3. 明确不包含

```text
Windows 与 Android 数据同步
用户账户、远程 API、云后端
真正的 AI Evaluation / Planner
面向用户展示的 Mock Evaluation
Agent / MCP
ContextState / ProgressState
PREFERRED 时间策略与 Preferred Window 调度
到点自动写入 START（固定时间只提醒，等用户确认）
Goal Outline 的自动 Merge / Replace
完整 Plan 编辑器
多端差异化界面
等级 / 金币 / 签到 / 排行榜
```

**这些能力不得以空目录、占位接口、未使用字段的方式提前进入工程。**

补充说明：

- **不生成模拟评价。** 真实 AI 未接入时，Result 页明确显示"智能评价暂未接入"，绝不伪造分数或评语。
- **不做从 GoalNode 批量生成 Mission。** GoalNode 是长期路线图，用户只为当前准备执行的节点创建 Mission。
- **不提前设计未来的 AI 数据结构。** 见 [数据模型 §1.6](数据模型.md)。

---

# 4. Source of Truth

```text
Goal Outline JSON   = 外部输入与导入快照 ≠ 运行时业务真相
本地规范化数据       = 当前业务事实
ExecutionEvent[]    = 执行历史的唯一来源
```

GoalNode 必须规范化保存，Mission 通过 `goalId / goalNodeId` 关联。

**页面不得直接读取 Raw JSON 驱动业务。** 导入后 Raw JSON 只作为追溯记录，不参与查询。

Mission 的编辑表单可以复用已有字段，但不得编造步骤或验收标准。

---

# 5. VerificationPolicy 结果矩阵

```text
SELF_REPORT / OPTIONAL_EVIDENCE / REQUIRED_EVIDENCE
```

| Policy | 用户报告完成后的结果 |
| --- | --- |
| SELF_REPORT | CLOSED + NOT_REQUIRED |
| OPTIONAL_EVIDENCE / 选择不提交 | CLOSED + NOT_REQUIRED |
| OPTIONAL_EVIDENCE / 选择提交 | EVIDENCE_PENDING + NOT_SUBMITTED |
| REQUIRED_EVIDENCE | EVIDENCE_PENDING + NOT_SUBMITTED |

只有 REQUIRED_EVIDENCE 受 Evidence Deadline 约束。详见 [领域模型 §13-14](领域模型.md)。

---

# 6. 验收标准

## 6.1 Goal 与导入

- 可以手动创建 Goal，并可以修改标题、说明、Why
- 可以通过系统文件选择器读取 `.json`，也可以粘贴文本
- 非法 JSON 不写入任何业务数据
- 合法 JSON 先展示 Tree Preview，用户确认后才写入
- 导入是一次性事务：失败不留半个大纲
- GoalNode 的父子关系、顺序和描述在重启后保持
- Goals 只提供一个"添加目标"主入口，点击后选择"手动新建"或"从 JSON 导入"
- Goal Detail 的"新增根节点"位于节点树语境内

## 6.2 Mission 创建

- 可以创建不绑定 Goal 的临时 Mission，也可以从 GoalNode 创建
- 从 GoalNode 进入时自动预填节点标题、节点说明与 Goal 的 Why；Steps 与验证标准仍由用户填写
- 长期 GoalNode 不会被静默批量转换为 Mission
- 用户可以填写 Title、Why、Objective、Steps、验证标准、VerificationPolicy、日期、计划时长与时间策略
- REQUIRED_EVIDENCE 必须设置 Evidence Deadline
- 保存时 Mission、ExecutionPlan、ScheduleRevision 要么全部存在，要么全部不存在
- 保存成功后 Mission 出现在对应日期的 Today
- 创建页明确展示计划日期；未开启固定时间时保持 FLEXIBLE，由用户手动 START

## 6.3 Lifecycle 与恢复

- START / PAUSE / RESUME / EXTEND / END 全部持久化为执行事件
- Running 状态关闭并重新打开后，Elapsed 继续按真实事件时间计算
- Paused 状态关闭并重新打开后，暂停期间不增加 Focus
- Evidence Pending、Evaluation Pending、Closed 状态重启后保持
- Evidence、FailureRecord 与血缘关系重启后保持
- 未接入真实 AI 时明确显示"智能评价暂未接入"，不生成、不展示模拟评价
- 启动时补算已错过的 Required Evidence Deadline，不改写已完成的执行事实

## 6.4 Evidence

- 支持文字、代码、图片、文件、手动记录
- 附件复制到应用私有目录，数据库只保存相对 storageKey
- 单附件不得超过 20 MB
- Finalize 前明确提示：Draft 尚未进入正式历史
- Finalize 后才能进入等待评价；Draft 可以被自由增删改

## 6.5 执行活动与进度

- 首页展示最近 7 天计划 / 完成情况，以及近 30 天完成格子
- **完成数来自真实 END 事件，不由计划日期推断**
- Goal / GoalNode 显示关联 Mission 的完成记录，不使用掌握度措辞

## 6.6 通知

- 创建 FLEXIBLE Mission 不安排开始提醒
- 创建未来 FIXED Mission 保存固定开始时间，到点显示"开始"通知
- Fixed 通知提供"开始 / 延后 15 分钟"；延后只重排提醒，Mission 仍为 Ready，且**不写 START Event**
- 点击"开始"后只产生一条 START
- 点击"停止"立即 PAUSE，再显示结果确认；取消后保持 Paused
- 完成或未完成后，执行通知消失
- Running / Paused 状态下杀进程重启，状态、Focus 与通知一致
- 通知权限被拒绝时，不回滚 Mission 或执行事件，并给出清楚提示

## 6.7 数据安全

- 正常启动不自动加载或覆盖任何示例数据
- 任意事务失败不留下半条业务链
- 未识别的枚举、损坏的关系、不支持的存储版本必须明确失败，不静默猜测
- 正式页面不提供"一键清空全部用户数据"
- 存储升级不得删除或重建用户数据

## 6.8 界面

- 页面标题、字段标签、按钮、帮助文字、日期选择器和业务错误提示使用中文
- `Mission Book` 品牌名与用户数据不强制翻译
- 窄屏（Android 常见宽度）下不出现布局溢出，键盘弹出时内容可滚动且底部操作可达
- 视觉基调以 [界面与交互](界面与交互.md) 与 `ui设计手册/` 为准

---

# 7. 完成定义

> 用户今天创建一个 Mission，执行一半退出程序，重新打开后仍能看到正确状态、时间和历史，并继续完成整个闭环。

## 自用验收链路

在 Windows 与 Android 上分别手工走一遍：

```text
创建真实 Goal / 导入大纲
   ↓
手动创建真实 Mission
   ↓
Start → Pause 或保持 Running
   ↓
关闭应用 → 重新打开 → 继续并完成
   ↓
提交 Evidence / 看到 Result
   ↓
再次重启仍能查看全部历史
```

这条链路两端都走通，这一版才算完成。
